# Code QA: voice_state / prosody / tuning scripts (2026-10-10)

Scope: backend/detectors/voice_state.py, prosody.py, tests/test_voice_state.py, scripts/{public_checks,tune_voice_state,fetch_open_data}.py.
Report only; no code edited. Software-correctness review, not scientific validation. All results EXPLORATORY.
Verified: `pytest -q ../tests/test_voice_state.py` gave 7 passed in 1.30 s. Not run: ruff, mypy, vulture, bandit, coverage, mutation spot-checks (budget), the scripts themselves (data/external not exercised). Review is manual.

## MAJOR

1. voice_state.py:85-88, prosody.py:26 - non-finite or non-float audio crashes the detector. NaN/inf samples make `librosa.yin` raise (librosa rejects non-finite audio; UNVERIFIED for this librosa version, test it). `analyze` has no try/except, so one bad frame raises into C's pipeline. int16 input is not rejected either: clipped_frac would read ~1 and the clip is silently labelled "clipped". Fix: in `extract_features`, return None (or a "bad audio" problem) if `not np.isfinite(audio).all()`; add tests for NaN, inf, empty, all-zero.
2. prosody.py:26 - CPU-bound `extract_features` (yin + framing, up to ~10 s audio) runs synchronously inside `async analyze`. base.py:6 says blocking inference must use `asyncio.to_thread`. Risk: stalls the event loop and websocket during a call. Fix: `await asyncio.to_thread(voice_state.extract_features, ...)`. Interface risk for C only if they assume sync; no change to events.
3. tune_voice_state.py:14 and :11-14 - the amended selection rule was written after seeing the first run, and the first-run output was discarded. If the first run also printed the report half, the report half is not fully held out from rule design, and the deviation is not auditable. Fix: state in the docstring whether report-half numbers were seen before the amendment; if so, label report_half "seen" and rely on fresh data for any claim.
4. public_checks.py:83-85 with tune_voice_state.py:82 - possible speaker leakage between halves. Split is by index parity of a shuffled list of (meeting, speaker) keys. If AMI speaker_id repeats across meetings (same participants in several sessions of a scenario, likely but UNVERIFIED), the same person lands in both halves, and meeting/room/channel is shared too. Fix: group by speaker_id (and ideally meeting) before splitting; assert the two sets are disjoint; print the overlap count. RAVDESS split by actor (1-12 / 13-24) is clean.
5. public_checks.py:149-152 vs voice_state.assess - RAVDESS rows bypass `quality_problems` (trim at top_db=30, then only None/NaN f0 is dropped). Production would reject trimmed clips under 1 s, noisy (p95-p10 < 10 dB) or low-voiced clips. Tuning and report-half RAVDESS rates are therefore on a different population than what the detector actually scores. Also `librosa.effects.trim` is not in the production path. Fix: apply `quality_problems` in `ravdess_table`, report how many clips fall out, and rerun.

## MINOR

6. voice_state.py:56-65, :106 - `snr_db` is the p95-p10 frame-dB spread (dynamic range), not SNR. Continuous loud speech with no pauses reads as "noisy"; a clean recording with long pauses passes. Rename (`dyn_range_db`) or document; user-facing reason says "noisy audio".
7. voice_state.py:122-127, :164 - baseline frozen after the first 3 usable utterances (by design, documented). Consequences: (a) a caller already agitated at call start, or a greeting with different delivery, becomes the reference and later change is invisible or inverted; (b) no drift handling in long calls. State this limit in the user-facing text/plan. 3 utterances with MAD floor is a thin baseline (tune shows n=5 has lower AMI false alarms, 0.028 vs 0.094 at z=2.5, similar RAVDESS gap 0.578 vs 0.593; n=3 chosen by the rule, not by robustness).
8. prosody.py:25 and core CallContext (pipeline.py:139,161) - baseline lives in `ctx.state["prosody"]`; pipeline.py:161 creates a fresh CallContext, so a new call resets it (good, did not run it). Risk: one baseline per CallContext assumes a single speaker. If the context ever carries both agent and caller audio, the baseline mixes speakers. Confirm with C that only the caller's utterances reach this detector. No test covers reset.
9. voice_state.py:86-88 - yin frames are centre-padded while `_frames` frames are not; `n=min(...)` aligns them by index, so rms/f0 are offset by about 1-2 frames (10-20 ms). Harmless for medians, but state it. `librosa.feature.rms` and `yin` also both pad with reflect, which is untested for 800-1023 sample clips.
10. voice_state.py:172 - `assert f is not None` is stripped under `python -O`; quality_problems already guarantees it. Replace with an explicit type narrowing.
11. prosody.py:20 - `min_baseline_utts or default` turns 0 into 3. Use `is None`.
12. tune_voice_state.py:36-38, :40 - tuner mutates module globals of voice_state (process-global, not reset after the loop; leaves the last setting applied). Fine for a script, unsafe if imported. Restore in a `finally`. The defaults in voice_state.py (2.5/3/2/3) equal `chosen`, but nothing enforces they stay in sync; add a test reading results/tune_voice_state.json or a note.
13. tune_voice_state.py:63-64, :99 - actors with fewer than `n` pool clips are silently skipped, so the actor set differs across grid settings, and `n_actors` in report_half is hardcoded `len(rep_act)` (12) rather than the number actually used. Report actors used per setting.
14. tune_voice_state.py:68-72 - RAVDESS flags are single-clip (sustain not applied), so `sustain_n` is not scored on RAVDESS; it is chosen only by the AMI false-alarm constraint. Selection metric (high-arousal share minus calm share) rewards flagging loud/animated acted speech; it is not stress. Already labelled exploratory; keep that wording.
15. tune_voice_state.py:99 - 15 AMI speakers in report half, CI [0.004, 0.224]; the claim "<= 0.15 false-alarm rate" is not supported by the CI upper bound. Report as is.
16. public_checks.py:211 - JSON key says `z>=2` but code uses `vs.Z_FIRE` (2.5, or whatever is last mutated). Label mismatch. Also docstring (line 14) says it writes results/public_checks.md; no code does.
17. public_checks.py:105,109-113 - empty `usable`/`rates` gives NaN mean/np.percentile errors; `ami_utterances` keeps all merged audio in memory and the 10 s cap is checked only when the next segment arrives (merged clips can exceed 10 s). `quick` still reads all shards.
18. public_checks.py:227,229 - provenance is good (sha+dirty flag, seed, versions) but results ran on a dirty tree (git status shows many untracked/modified files), so sha does not reproduce it. tune_voice_state.json has no sha, versions, command, or data manifests. Add the same fields; commit before the final run.
19. fetch_open_data.py:40 - `hf_hub_download` with no `revision`: dataset can change under the same shard name; the manifest records sha256 of what was fetched but no commit hash. Pin `revision=`. Manifest is overwritten each run, so a second invocation with different shards drops the earlier entries (line 43-44). LibriSpeech is required by public_checks (line 119) but fetch_open_data has no command for it.
20. fetch_open_data.py:59-65 - `urlretrieve` with no timeout; a partial zip left on disk fails md5 forever with no cleanup/retry; `extractall` without path check (md5-pinned, so low risk); `read_bytes` loads the whole zip into memory (use the chunked sha helper). Also the expected md5 is copied "from the Zenodo record API"; source quote not recorded here (UNVERIFIED by me).
